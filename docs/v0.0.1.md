# JellyZero v0.0.1 — local Spotify-controller prototype

No authentication, Spotify API, network calls, audio decoding or Hermes integration.
All track/device data and playback state are fixtures. The device page explicitly states `DEMO DEVICES / no Spotify connection`; selecting a device does not transfer real playback.

## Controls

| Key | Now Playing | Device selector |
| --- | --- | --- |
| 4 | Exit application | Previous device (wraps) |
| 5 | Previous fixture track (wraps) | Confirm selection |
| 6 | Play/pause local state | Next device (wraps) |
| 7 | Next fixture track (wraps) | Cancel / back |
| 8 | Open device selector | No action |
| Left / Right | Seek -/+10 seconds | Previous / next device |
| Up / Down | Volume +/-5 percentage points | Previous / next device |
| Enter | No action | Confirm selection |
| ESC | Hold to exit; short press stays on home | Cancel / back |

The simulator's on-screen keys and clickable navbar are also supported.
On the virtual Cardputer keyboard, Fn+Z/C are Left/Right and Fn+F/X are Up/Down.
The template HELP and screenshot shortcuts are retained.

Startup: playing (local demo only), MONEY FOR NOTHING / Dire Straits / Brothers in Arms,
01:42 of 05:06, volume 50%, Desktop (demo). Progress is derived from seconds,
not a separately hard-coded percentage. Playback time is intentionally static:
play/pause changes local state only; seek and track changes update the time/bar.
Volume and seeking are clamped. Device selection is staged until confirmed;
cancel preserves the previous device. Page changes preserve playback state.

## Architecture

- `FakeMusicProvider` contains fixtures and local music state, without LVGL.
- `BaseViewModel` routes music actions and publishes a reactive change subject.
- `AppleScreen` renders Now Playing; `ButterScreen` renders demo devices.
- Existing BaseScreen, titlebar, IconButton, screen manager and input router remain.
- Reference-style split player/queue layout, lowercase metadata, purple progress bar.
- Static demo artwork replaces the disc to match the latest graphical reference. It is a 64x68 crop of the artwork area in the user-provided mockup; it is not fetched from Spotify and does not change per fixture track.
- ButterScreen labels align directly over physical keys 4-7 (LCD x=49,106,163,220), using 57px key spacing. The unused noninteractive slot is on the right.
- Five bottom controls: Exit, Previous, Pause/Play, Next, Dev. Dev opens ButterScreen.
- Queue shows the next five local fixture tracks, updating with Previous/Next; long entries are clipped with ellipses.
- Now Playing shows volume as a bare percentage, adjusted with keyboard Up/Down. Demo status and active device are shown in ButterScreen.
- No audio visualizer or real Spotify queue data.
- Real Spotify PKCE/API work and a generalized provider interface remain v0.0.2 work.

## Build and tests (MSYS2 MINGW64)

Close the running simulator before linking on Windows (it locks its EXE/DLLs).
Keep the MinGW toolchain on PATH and VCPKG_ROOT set to the existing vcpkg checkout.

```bash
cmake --preset win32-mingw64
cmake --build --preset win32-mingw64-dbg
ctest --test-dir build/mingw64 -C Debug --output-on-failure
python tests/evdev_enter_test.py --lvgl-dir .cache/win32-mingw64-deps/lvgl-src
./build/mingw64/Debug/jellyzero.exe
```

The desktop-only CTest executable constructs real LVGL screens and uses the
existing virtual keypad/input router. It checks metadata, layout bounds, progress,
play/pause, track wrapping, seek/volume limits, held keys, device confirm/cancel,
repeated screen replacement, navbar registration, control order, clicks, static artwork orientation and physical-key alignment and help labels. It needs no
Spotify account, SDL window or hardware. `BUILD_TESTING=OFF` omits this target.
Actual CardputerZero deployment and physical-device controls are not verified.

The standalone evdev regression compiles the actual translation function with Linux ABI fixtures. It covers Enter/keypad Enter translation, not Linux device reads or physical input.

The ASCII experiment has been removed. The larger graphical type, purple progress bar, and split player/queue layout follow the user-provided graphical reference.

Device navbar labels are UP / SELECT / DOWN / BACK; numeric key prefixes are omitted without changing key4-7 bindings or alignment. The Now Playing percentage is playback volume; the titlebar percentage remains battery level.

Now Playing maps physical keys4-8 to Exit / Previous / Play-pause / Next / Dev. Its icons align at LCD centers49,106,163,220,277. ButterScreen retains keys4-7 for UP / SELECT / DOWN / BACK and an inert key8 slot.

## Final local review

See [security and efficiency review](v0.0.1-audit.md) for fixes, reproducible tests,
measured heap/timer behavior and remaining release gates. MinGW Debug and Release
both passed 2,149 UI checks and all three CTest suites. PNG-error cleanup and raw
evdev translation regressions are now registered with CTest (the latter when
Python and GNU C++ are available).

Device packaging defaults to no systemd service; existing caches must be configured
with `-DAPP_INSTALL_SYSTEMD_SERVICE=OFF`. Device installation omits desktop-only and
unused assets. Its LVGL 9 image cache is bounded at 64 KiB. Desktop tests do not
certify hardware memory, rendering or timing.
