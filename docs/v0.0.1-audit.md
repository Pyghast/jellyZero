# v0.0.1 security and efficiency review

## Verdict
Ready to preserve as a **local UI prototype/source milestone**, not a hardware-certified release or Internet-connected client. No Spotify/API/authentication/audio support was added. No Git commit, remote, push, tag or GitHub repository was created.

Reviewed first-party code, input/observer lifetimes, dependencies, packaging, assets and file writes. Used Gitleaks, MinGW Debug/Release builds, real LVGL integration tests and desktop process sampling. This is not an exhaustive penetration test or dependency-CVE certification.

## Fixed findings
- **Vulnerable libpng:** upgraded vcpkg 1.6.48 to 1.6.58 and rebuilt. The prior version is affected by CVE-2025-65018, relevant to the desktop shell loader if an attacker can replace an asset. Verified the actual Debug simulator DLL reports 1.6.58 and matches the installed dependency DLL. This does not update Linux device libraries.
- **Build integrity:** LVGL 9.5.0 and fmt 10.1.1 now use exact commits. BSP v0.0.4 downloads require its recorded release-asset SHA-256 and TLS verification. Controlled local-archive tests verified rejection before extraction on mismatch and successful extraction on a matching hash. The real 435 MB BSP was not downloaded/cross-built; existing sysroots are not reverified.
- **Privilege defaults:** packaging no longer installs a systemd service by default. Existing CMake caches can retain ON: explicitly configure `-DAPP_INSTALL_SYSTEMD_SERVICE=OFF`. This does not disable an existing installed service. The optional service still needs non-root device access and sandboxing before use.
- **PNG error safety:** moved the scanline vector before libpng's setjmp boundary. A deterministic actual-libpng write-error regression failed before the fix and passes afterward, preventing destructor-skipping longjmp behavior.
- **Idle redraws:** clock/status text setters skip identical values. The zero-LCD-flush regression failed before the fix and now passes. Polling and input intervals remain unchanged.
- **Device image cache:** replaced obsolete `LV_IMAGE_CACHE_DEF_SIZE` with LVGL 9's byte-based cache: 64 KiB plus eight headers. Actual hardware-config preprocessing verifies these values. The cover has 17,408 decoded pixel bytes. This trades bounded retained memory for avoiding repeat decoding; device throughput is unmeasured.
- **Lean packaging:** explicit asset allowlists exclude desktop shell art, unused keyboard fonts/audio and the abandoned disc. Generated install rules were checked. This removes **1,093,795 uncompressed installed-file bytes**, including duplicate launcher artwork—not measured .deb compression or RAM savings.
- **Publishing hygiene:** `.gitignore` excludes common environment, credential and private-key files alongside existing build/cache/dist rules. Ignore rules do not untrack committed secrets and are not a substitute for scanning.

## Verified results
- Full MinGW Debug and Release application builds succeeded; both CTest runs passed **3/3 suites**: UI, forced PNG-error cleanup, raw evdev Enter mapping.
- UI: **2,149 checks** in each configuration.
- 500 rendered asynchronous Apple/Butter round trips: Debug LVGL heap **49,328 -> 49,512 bytes**, peak **66,112**, timers **5 -> 5**; Release **49,552 -> 49,400 bytes**, peak **66,440**, timers **5 -> 5**. Every trip checks pages, timer count, bounded growth and heap integrity. These are harness LVGL allocator figures, not total process/device RAM.
- Initial stress-test growth was an async-callback backlog from skipping the event loop. Production pumps LVGL. The corrected test exercises that path; no production lifetime rewrite was justified.
- Final Windows Debug idle sampling: psutil reported 0.0% one-core CPU over three 3-second windows after startup; RSS 119,066,624 bytes; no observed IPv4/IPv6 connections. SDL, shell, drivers and thread pools are included. Do not extrapolate this to CardputerZero or claim a reliable before/after speed ratio.
- Gitleaks 8.30.1: Git history and nonignored publication tree scanned with redacted reporting; no detected secrets. Final results: ignored `.cache/audit/secret-scan-final.json`.
- `git diff --check` passed. vcpkg emitted community-MinGW/legacy-CRT packaging warnings; this is not a warning-free toolchain certification.

## Remaining risks and release gates
1. **Device measurements:** physical-key latency, CPU, RSS, power, CJK fonts, framebuffer/DRM and system libraries remain unverified. The 32 MiB LVGL pool, 5 ms loop sleep, refresh rate and glyph cache were not cut based on desktop guesses. Test a device Release build before calling it hardware-ready.
2. **Local file writes:** config writes still truncate in place and follow links; screenshots use nonexclusive names and a shared temporary-directory fallback. Use an ordinary user and trusted output/asset directories. Atomic/no-follow/exclusive writes remain hardening work for privileged or multi-user deployments. No remote input reaches these paths in this demo.
3. **Asset precedence:** development source paths remain compiled in and searched before installed assets. Never run elevated against writable source/asset trees. Installed-only asset resolution remains production work.
4. **Linux dependencies:** vcpkg upgrades the simulator, not the BSP/runtime libraries. Check distribution security updates/backports before distributing device packages or accepting remote artwork.
5. **Publication:** preserve template MIT LICENSE and attribution. Confirm redistribution rights for the reference-cropped demo cover or replace it before public release. Review inherited asset notices; the Phosphor notice is abbreviated. Store author/source/description/license and package maintainer fields remain placeholders; the current validator does not reliably reject them. GitHub source backup is not store submission.
6. **Future networking:** OAuth PKCE/token storage, TLS, request bounds/timeouts, response validation and untrusted artwork limits need a separate review before Spotify integration.

## Reproduce (MSYS2 MINGW64)
Close the simulator first; keep MinGW on PATH and VCPKG_ROOT configured.

```bash
cmake --preset win32-mingw64 -DAPP_INSTALL_SYSTEMD_SERVICE=OFF
cmake --build --preset win32-mingw64-dbg
ctest --test-dir build/mingw64 -C Debug --output-on-failure
cmake --build --preset win32-mingw64-rel
ctest --test-dir build/mingw64 -C Release --output-on-failure
```

Raw evdev test registration requires Python and GNU C++; it checks translation with Linux ABI fixtures, not physical device reads. Local evidence is under ignored `.cache/audit/` and CTest logs.
